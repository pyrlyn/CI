# План: двойная лицензия, CLA и идеи из Empryo для rtok/cox

План по rtok и cox: лицензирование, CLA и идеи из Empryo. Составлен 2026-10-02; статусы обновляются по мере работы. Ссылки на PR будут добавлены, когда их откроют.

## 1. Двойная лицензия и синхронизация файлов лицензий — 🟡 в работе

- [ ] Эталонные файлы `LICENSE-GPL` (GPL-3.0) и `LICENSE-COMMERCIAL` лежат в `pyrlyn/infra`. Это единственный источник правды.
- [ ] Workflow в infra (`license-sync.yml`). Когда эталон меняется, workflow открывает или обновляет автоматический PR в каждом GPL-репозитории org, как это делает Dependabot. Если защита веток позволяет, PR мержится сам.
- [ ] Reusable workflow `license-check.yml`. CI в GPL-репозитории падает, если любой из двух файлов отличается от эталона.
- [ ] В README каждого GPL-репозитория, в том же PR, появляется строка «Commercial use requires a separate paid license — see LICENSE-COMMERCIAL». Строку держат маркеры `license-sync`. Если у README есть переводы, строка добавляется и в них.
- [ ] Репозитории не под GPL (MIT и другие, по LICENSE и полю `license` в Cargo.toml или package.json) пропускаются. Они будут перечислены в отчёте, решение по ним за Иваном.
- Где: `pyrlyn/infra` плюс PR в каждом GPL-репозитории. Мержить без решения Ивана нельзя.

## 2. Заголовки лицензии в исходниках — 🟡 в работе (draft PR)

- [ ] В каждом GPL-репозитории открывается отдельный draft PR. В заголовок файла пишутся год, `Ivan Tugay`, `SPDX-License-Identifier: GPL-3.0-or-later`, фраза «Licensed under GPL-3.0 or later» и ссылка на полный текст.
- [ ] Пропускаются сгенерированные, vendored и fixture-файлы, lock-файлы, JSON и файлы, где заголовок уже есть.
- [ ] ⚠️ Если в Cargo.toml указано `GPL-3.0-only`, а не `-or-later`, PR это помечает. Решает Иван, молча ничего не меняется.
- [ ] Можно предложить `OR LicenseRef-Commercial` в SPDX. Это пока только предложение, не применяется.
- [ ] По желанию: проверка наличия заголовков в `license-check.yml`, по умолчанию выключена.

## 3. CLA — 🟡 в работе (draft PR)

- [ ] Текст в `CLA.md` (английский, основной) и `CLA.ru.md` (русский, при расхождении действует английский). Автор вклада даёт Ивану Тугаю бессрочную безотзывную лицензию на использование, перелицензию и коммерческое использование, включая патентную. Сам вклад остаётся под GPL для всех. Перед применением текст должен проверить юрист.
- [ ] Подпись через GitHub Action CLA Assistant Lite (`contributor-assistant/github-action`): reusable workflow в infra и caller-workflow в GPL-репозиториях. Подписью служит GitHub-аккаунт, PR без подписи помечается. Боты в allowlist.
- [ ] Вручную, Иван: завести секрет с токеном, выбрать место хранения подписей (ветка в infra или отдельный репозиторий) и сделать проверку CLA обязательной через rulesets. Инструкция будет в `docs/cla.md` в infra.

## 4. Идеи из Empryo для rtok и cox — 🟢 исследование готово, 🟡 детальная проработка в работе, ⚪ реализация не начата

Empryo (proxysoul/Empryo) распространяется под **BSL 1.1**, поэтому код копировать нельзя. Берём только идеи и переписываем на Rust с нуля.

14 идей, которые переносятся в Rust:
1. Персонализированный PageRank по файлам: веса по фокусу хода, тёплый старт, связи только по типам весят 0.3×.
2. Веса связей с учётом IDF и уверенности: импорт против совпадения по имени, общие имена вроде `new` отсекаются.
3. Пары файлов, которые меняются вместе, из `git log` (300 коммитов, кэш по HEAD).
4. Метка охвата `(→N)` и бюджет карты: блоки подбираются двоичным поиском, кэш.
5. Триграммный префильтр для grep.
6. Поиск дублей через MinHash. В Empryo PR #220 ускорил холодный скан примерно в 12 раз (33,2 → 2,7 с).
7. Ответы на grep из индекса символов.
8. Дельта диагностик после правки.
9. Цепочка запасных вариантов LSP → AST → tree-sitter → regex и чистка зависших LSP-серверов.
10. Составные инструменты `rename_symbol` и `project`.
11. Сжатие контекста без вызова модели (накопительное состояние сессии).
12. Память на RRF по четырём сигналам: слова, триграммы, связь с файлами, совместные изменения.
13. Устойчивые правки: нечёткие пробелы, защита по хешу, стек отмен.
14. Сжатие вывода команд с сохранением стектрейсов.

### Задачи для rtok (⚪ к выполнению)
1. Карта репозитория по PageRank между файлами и метка `(→N)`. Персонализированные оценки не сохранять (см. Empryo #228). Размер M.
2. IDF и уверенность связей в `callers`, `impact` и `explore`. Размер S–M.
3. Таблица совместных изменений для карты, `impact`, `affected` и памяти. Размер M.
4. Ответ на grep из индекса символов вместо полного запрета в guard. Размер S–M.
5. Связь заметок памяти с файлами (`note_files`) и два новых сигнала RRF. Размер S–M.
6. Триграммный префильтр для `read search` с проверкой выигрыша. Размер M.
7. `rtok graph dupes` на MinHash и связь тестов с кодом по именам файлов. Размер M.

### Задачи для cox (⚪ к выполнению)
1. Карта репозитория по графу и PageRank вместо сортировки по свежести, с персонализацией только по git. Возможно, общий crate с rtok. Размер L/M.
2. Сжатие без вызова модели для разделов «файлы» и «ошибки». Размер M.
3. Дельта диагностик в выводе `edit` и `write`. Размер M.
4. Навигация через LSP и `rename_symbol`. Размер L.
5. Инструмент `check`: тесты, сборка, линтер. Размер M.
6. `read` и `edit` по символу. Размер M.
7. Схлопывание повторов в выводе через правила `cmd` из rtok. Размер S.

Сейчас идёт детальная проработка: где задача встанет в коде, как её сделать на Rust, критерии приёмки и что брать первым. Результат будет добавлен сюда.

## 5. Сканирование лицензий зависимостей — ⏸ на паузе, [license-scanning.md](license-scanning.md)

- Исходная просьба: активно проверять только GPL, MIT и Apache пропускать.
- Открытый вопрос: ронять CI на GPL-зависимости или только показывать её в отчёте?
- ⚠️ GPL-зависимость ломает коммерческую лицензию rtok и cox.
- Предложение: `cargo-deny` в infra. MIT и Apache не трогаем, GPL показываем в отчёте и роняем на нём CI.
